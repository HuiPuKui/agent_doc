# Agent 面试题

### 1. 什么是 Agent? 与大模型有什么本质不同？

大模型是每次你问他一个问题他回答一个问题，每次都是独立的

Agent 是有主动性的，Agent 以大模型作为底层大脑，你给他一个目标，他会自己进行分析、拆解，通过调用工具、记忆管理来一步步感知上下文环境，直到完成。

### 2. Agent 的基本架构由哪些核心组件构成

* LLM：底层大模型，整个系统的大脑，负责任务理解和决策
    * system prompt: 模型的角色提示词很重要
    * 推理能力
    * 上下文窗口

* 工具：让 Agent 和外部世界交互，搜索、执行代码、调用API等
    * description：工具定义很重要，一定要描述清楚

* 记忆：让 Agent 在任务执行过程中保持状态  
    * 短期记忆
    * 长期记忆

* 规划模块：负责把复杂目标拆解成可执行的步骤
    * CoT：Chain of Thought 思维链
    * ToT：Tree of Thought 思维树
    * Plan-and-Execute、ReAct 一般结合使用

### 3. Workflow，Agent，Tools 这三个的概念和区别介绍一下？

* Tools: 最小的能力单元，封装好的可调用函数
    * 给大模型看的函数
    * 有描述来描述函数作用

* Agent: 一个完整的决策系统
    * LLM 作为大脑
    * 自己判断何时执行 Agent

* Workflow: 更上层的编排框架，把 Agent、LLM、Tools 组织成一条确定性流程
    * 提示链
    * 路由
    * 并行化
    * 编排者-工人（Orchestrator-Workers）
    * 评估者-优化者（Evaluator-Optimizer）

### 4. 了解哪些其他的 Agent 设计范式？Agent 和 Workflow 的区别是什么？

* ReAct：
    * 推理 - 执行 - 观察
    * 每一步都是局部最优解，复杂任务容易忘记最初的目标是什么，或者反复在几个工具之间打转

* Plan-and-Execute
    * 规划 - 执行
    * 动态重规划
    * 如果规划本身就错了，很难挽回

* Reflection
    * 反思
    * 还有一种是 Reflexion

* 一般很多系统都是混合使用的

Agent 模式灵活但不可控，排查问题困难

Workflow 是认为先规定好节点，出问题容易排查，易把控

通常做法是 Agentic Workflow，整体用 Workflow 控制主流程，部分需要灵活处理的节点使用 Agent 能力。

### 5. Agent 推理模式有哪些？ReAct 是啥？具体是怎么实现的？

* CoT：Chain of Thought
    * Zero-shot Cot：在 prompt 最后加上「让我们一步步思考」
    * Few-shot Cot：在 prompt 给几个带有完整推理过程的例子，让 LLM 来模仿
    * 只能以来自己训练数据中的知识，无法调用工具，于是就催生出来了 ReAct

* ReAct：Reasoning and Action
    * 最初版本的模型是根据特定格式来的比如 Thought:xxx Action:xxx
    * 目前的模型基本都支持 Function Call，可以直接返回结构化数据
    * 容易跑偏，没有回头检查的机制

### 6. ReAct、Plan-and-Execute、Reflection 三种范式有什么核心区别？实际项目中该如何选型？

* ReAct 依旧介绍，说明优点和缺点
* Plan-and-Execute 依旧介绍，说明缺点和优点
    * Replan 动态重规划
* Reflection 依旧介绍，说明优点和缺点
    * Reflexion

要根据场景选择，不要无脑混用，正常 ReAct，如果复杂任务上 Plan-and-Execute，高要求再上 Reflection

### 7. 复杂任务怎么做的任务拆分？为什么要拆分？效果如何提升？

为什么拆：LLM 的 context window 有上限，人物越大中间状态越多、越容易出错，而且拆开后每步可以独立验证和重试。

怎么拆：

* 静态拆分：人工来做类似 workflow，写死步骤，好处就是逻辑清晰可控，而且容易调试
* 动态拆分：就是 Plan-and-Execute，完全由 LLM 自己规划，针对不同人物灵活拆分，缺点是不稳定
* 拆分时把握粒度很重要，要以原子操作为标准，不能太细也不能太粗

拆完要做的事：分析好各个节点之间的依赖，可以并行的并行做，可以节省时间

### 8. 请你介绍一下 AI Agent 的记忆机制，并说明在实际开发中应该如何设计记忆模块？

Agent 需要记忆来在多步任务中保持状态、跨任务累计知识

* 感知记忆：「当前这次调用的原始输入」
* 短期记忆：context window 里面的 message 列表，包括用户输入什么，模型输出什么，工具调用等等。
* 长期记忆：跨任务保留的信息，通常存在向量数据库、关系数据库或 KV 存储中。
    * 情节记忆：可以检索历史上的类似经历，参考上次是怎么解决的，避免重复踩坑。
    * 语义记忆：存的是从多次经历中提炼出来的通用知识和规律
    * 程序记忆：存的是怎么做某件事的操作流程
    * 情节记忆提供具体的参考案例，语义记忆提供抽象的知识规律，程序记忆提供可复用的操作流程。
* 实体记忆：比长期记忆更精炼，它不是存原文，而是把对话中出现的关键实体和事实主动提取出来。

实际设计时需要解决

* 存什么：「是否会让 Agent 做的更好」如：用户偏好、关键解决、决策、外部知识等
* 怎么存：根据信息的类型选择合适的媒介，不是全都往向量数据库中塞，语义化的内容可以存入向量数据库，结构化的或许更适合用 KV 存储
* 什么时候取出来用：
    * 「主动检索」任务开始前，用任务描述去检索相关记忆
    * 「被动触发」Agent 判断当前需要一些特定知识时，主动检索（将「查记忆」封装成工具提供给 Agent 调用）

### 9. Agent 的长短期记忆怎么做的？记忆是怎么存的？粒度是多少？怎么用的？

* 短期记忆：context windows 包括用户指令、模型思考、工具调用等等
    * 滑动窗口
    * 压缩
* 结构化工作记忆：一个区域专门放当前任务目标，一个区域专门放已确认的中间结论，一个区域放待验证的假设，每一步执行完之后，Agent 主动更新对应区域的内容
* 长期记忆：跨任务保留的信息，通常存在向量数据库、关系数据库或 KV 存储中。
    * 情节记忆：可以检索历史上的类似经历，参考上次是怎么解决的，避免重复踩坑。
    * 语义记忆：存的是从多次经历中提炼出来的通用知识和规律
    * 程序记忆：存的是怎么做某件事的操作流程
    * 情节记忆提供具体的参考案例，语义记忆提供抽象的知识规律，程序记忆提供可复用的操作流程。
    * 粒度上一般按「一次完整交互」或「一个关键事件」为单位存，太细噪音大，太粗丢失细节，应该根据实际业务调整。

### 10. 什么是 Multi-Agent？

Multi-Agent 就是多智能体协作完成任务，每个智能体负责一部分任务来完成任务

单个智能体在一些方面受限

* 上下文大小
* 单点能力

Multi-Agent 通过分工和并行，能处理复杂、长流程的任务

多 Agent 协作模式
* 顺序流水线
* 并行扇出
* 辩论/评审模式

多 Agent 系统的组织方式主要有两种
* 中心化：一般都选，调度清晰
* 去中心化：灵活但难排查

### 11. 说说 Single-Agent 和 Multi-Agent 的设计方案

* Single-Agent：
    * 本质是一个 LLM 加上一套工具跑一个决策循环
    * 优势是整个链路完全在你掌控之内，任务怎么走、用什么工具、什么时候结束，所有逻辑都是你在一个地方写清楚的，容易排查
    * 单 Agent 不适合的场景
        * 上下文很大，Agent 开始遗忘
        * 不同步骤需要不同的专业能力
        * 任务重有多个独立的子任务，理论上可以并行执行
* Multi-Agent：
    * 中心化方案核心是 Orchestrator 指挥 Worker（几乎所有正经项目都选择）
        * 静态路由：预先定义好的任务拆分和分配计划 if xxx
        * 动态规划：LLM 自己决定计划，以及每一个任务交给谁
        * 自适应编排：在动态规划的基础上，如果 LLM 觉得信息不够，可以选择追加一次任务
    * 去中心化方案会遇到很多问题
        * 任务分配没有协调、执行顺序无法保障、失败无感知等等
        * 不可控，无法排查

如何选型
* 任务流程是否明确，任务是否很长，是否需要多专业分工
* 渐进式演进：先用 Single-Agent 把任务跑起来，当你发现某一个环节成为瓶颈了，把它拆出来交给一个专门的 Worker

### 12. Agent 记忆压缩通常有哪些方法？

* 滑动窗口
    * 好处：极其简单
    * 坏处：硬截断，被截断的部分模型直接失忆
* 摘要压缩
    * 不直接丢弃超出窗口的历史，改为让 LLM 总结一下然后替换掉原始内容，但是会丢失细节
    * 层级式摘要：原文 - 中期摘要 - 长期摘要 一次精简
    * 工程一般 滑动窗口 + 摘要
* 重要性过滤，按价值筛选，不按时间筛选
    * 给每条会话记录打分，低于阈值的淘汰
        * 规则打分：程序判断
        * LLM 打分
* 结构化抽取
* 计算层的互补手段：缓存

### 13. 在工程实践中，为什么有时候选择「手搓」Agent，而不是直接用成熟框架？

首先要说框架是干什么的：像 LLM 调用、工具调用、记忆管理这些可以通用的部分，不用每次项目全都重写一遍，可以减少时间，而且可以让你快速将一套流程搭起来来验证你的想法。

但是随着业务一点点深入，有些问题就会浮现出来：
* 出现奇怪 bug 的排查，一层层跳最后跳到框架内部
* 版本升级，兼容性问题
* 性能的隐性开销

手搓的优势
* 完全掌握，链路透明，可控
* 稳定，不受框架升级影响，无兼容性问题
* 无多余开销

框架适合：
* 快速验证想法
* 周边工具依赖框架的生态，对核心影响不高

手搓适合：
* 上生产，性能和稳定性需要控制
* 业务逻辑需要定制
* 需要可控，整体链路需要能监控

实践中一般的选择：核心手写、周边借用

### 14. 如何赋予 LLM 规划能力

给 LLM 加规划能力主要靠这几种思路
* CoT：思维链，LLM 写出推理过程，一步一步线星推倒
* ToT：思维树，通过树状推理，边探索边评估边剪枝
* GoT：思维图，图结构推理，推理节点可以复用和合并，适合更复杂的任务

背后的原理是 transformer 的 next-token 预测机制

CoT 工程中最多，ToT 开销更多效果更好，GoT 目前还较学术，生产环境下一般没有

工程中真正使用的规划模式：Plan-and-Execute

### 15. 讲讲 Agent 的反思机制？为什么要用反思？具体怎么实现？

反思就是让 Agent 在完成一个步骤或整个任务后，自我评估输出质量，判断有没有问题，不达标就重试或调整策略。

因为 LLM 第一次输出不一定是最优的，加一轮自我检查能显著提升质量，相当于人写完东西自己再看一遍，但是代价是会多至少一次 LLM 调用，token 消耗和延迟都会增加，所以我在工程里只在质量要求高的关键节点启用反思，不是每步都做。

* Self-Refine
* Reflexion
* LATS（蒙特卡洛树搜索 和 反思结合）

### 16. 如何设计多 Agent 的协作与动态切换机制？

协作：
* 消息传递：Agent 完成工作后把结果发出去，下一个 Agent 订阅取用
* 共享状态：所有 Agent 维护同一个状态对象，记录任务进展和结果
    * 全局/局部状态
    * 只追加不覆盖

如果 Agent 之间依赖关系比较强，前一步的结果要直接传给后一步，用共享状态更直接。

如果希望 Agent 之间尽量解耦，互相不知道对方的存在，用消息传递更合适。


动态切换（靠 Orchestrator）
* 静态路由
* LLM 动态决策

实践是两种混用，主流程用静态路由保持稳定，边缘情况交给 LLM 动态决策
