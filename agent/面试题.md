# Agent 面试题

### 1. 什么是 Agent? 与大模型有什么本质不同？

大模型是每次你问他一个问题他回答一个问题，每次都是独立的

Agent 是有主动性的，Agent 以大模型作为底层大脑，你给他一个目标，他会自己进行分析、拆解，通过调用工具、记忆管理来一步步感知上下文环境，直到完成。

### 2. Agent 的基本架构由哪些核心组件构成

* LLM：底层大模型，整个系统的大脑，负责任务理解和决策
    * system prompt: 模型的角色提示词很重要
    * 推理能力
    * 上下文窗口

* 工具：让 Agent 和外部世界交互，搜索、执行代码、调用API等
    * description：工具定义很重要，一定要描述清楚

* 记忆：让 Agent 在任务执行过程中保持状态  
    * 短期记忆
    * 长期记忆

* 规划模块：负责把复杂目标拆解成可执行的步骤
    * CoT：Chain of Thought 思维链
    * ToT：Tree of Thought 思维树
    * Plan-and-Execute、ReAct 一般结合使用

### 3. Workflow，Agent，Tools 这三个的概念和区别介绍一下？

* Tools: 最小的能力单元，封装好的可调用函数
    * 给大模型看的函数
    * 有描述来描述函数作用

* Agent: 一个完整的决策系统
    * LLM 作为大脑
    * 自己判断何时执行 Agent

* Workflow: 更上层的编排框架，把 Agent、LLM、Tools 组织成一条确定性流程
    * 提示链
    * 路由
    * 并行化
    * 编排者-工人（Orchestrator-Workers）
    * 评估者-优化者（Evaluator-Optimizer）

### 4. 了解哪些其他的 Agent 设计范式？Agent 和 Workflow 的区别是什么？

* ReAct：
    * 推理 - 执行 - 观察
    * 每一步都是局部最优解，复杂任务容易忘记最初的目标是什么，或者反复在几个工具之间打转

* Plan-and-Execute
    * 规划 - 执行
    * 动态重规划
    * 如果规划本身就错了，很难挽回

* Reflection
    * 反思
    * 还有一种是 Reflexion

* 一般很多系统都是混合使用的

Agent 模式灵活但不可控，排查问题困难

Workflow 是认为先规定好节点，出问题容易排查，易把控

通常做法是 Agentic Workflow，整体用 Workflow 控制主流程，部分需要灵活处理的节点使用 Agent 能力。

### 5. Agent 推理模式有哪些？ReAct 是啥？具体是怎么实现的？

* CoT：Chain of Thought
    * Zero-shot Cot：在 prompt 最后加上「让我们一步步思考」
    * Few-shot Cot：在 prompt 给几个带有完整推理过程的例子，让 LLM 来模仿
    * 只能以来自己训练数据中的知识，无法调用工具，于是就催生出来了 ReAct

* ReAct：Reasoning and Action
    * 最初版本的模型是根据特定格式来的比如 Thought:xxx Action:xxx
    * 目前的模型基本都支持 Function Call，可以直接返回结构化数据
    * 容易跑偏，没有回头检查的机制

### 6. ReAct、Plan-and-Execute、Reflection 三种范式有什么核心区别？实际项目中该如何选型？

* ReAct 依旧介绍，说明优点和缺点
* Plan-and-Execute 依旧介绍，说明缺点和优点
    * Replan 动态重规划
* Reflection 依旧介绍，说明优点和缺点
    * Reflexion

要根据场景选择，不要无脑混用，正常 ReAct，如果复杂任务上 Plan-and-Execute，高要求再上 Reflection

### 7. 复杂任务怎么做的任务拆分？为什么要拆分？效果如何提升？

为什么拆：LLM 的 context window 有上限，人物越大中间状态越多、越容易出错，而且拆开后每步可以独立验证和重试。

怎么拆：

* 静态拆分：人工来做类似 workflow，写死步骤，好处就是逻辑清晰可控，而且容易调试
* 动态拆分：就是 Plan-and-Execute，完全由 LLM 自己规划，针对不同人物灵活拆分，缺点是不稳定
* 拆分时把握粒度很重要，要以原子操作为标准，不能太细也不能太粗

拆完要做的事：分析好各个节点之间的依赖，可以并行的并行做，可以节省时间

### 8. 请你介绍一下 AI Agent 的记忆机制，并说明在实际开发中应该如何设计记忆模块？

Agent 需要记忆来在多步任务中保持状态、跨任务累计知识

* 感知记忆：「当前这次调用的原始输入」
* 短期记忆：context window 里面的 message 列表，包括用户输入什么，模型输出什么，工具调用等等。
* 长期记忆：跨任务保留的信息，通常存在向量数据库、关系数据库或 KV 存储中。
    * 情节记忆：可以检索历史上的类似经历，参考上次是怎么解决的，避免重复踩坑。
    * 语义记忆：存的是从多次经历中提炼出来的通用知识和规律
    * 程序记忆：存的是怎么做某件事的操作流程
    * 情节记忆提供具体的参考案例，语义记忆提供抽象的知识规律，程序记忆提供可复用的操作流程。
* 实体记忆：比长期记忆更精炼，它不是存原文，而是把对话中出现的关键实体和事实主动提取出来。

实际设计时需要解决

* 存什么：「是否会让 Agent 做的更好」如：用户偏好、关键解决、决策、外部知识等
* 怎么存：根据信息的类型选择合适的媒介，不是全都往向量数据库中塞，语义化的内容可以存入向量数据库，结构化的或许更适合用 KV 存储
* 什么时候取出来用：
    * 「主动检索」任务开始前，用任务描述去检索相关记忆
    * 「被动触发」Agent 判断当前需要一些特定知识时，主动检索（将「查记忆」封装成工具提供给 Agent 调用）
